# 🎯 РЕАЛЬНОЕ РЕШЕНИЕ НА КОРНЮ: RAG ДЛЯ AI-ЮРИСТА

## 🔴 КОРНЕВАЯ ПРОБЛЕМА

### Почему текущее решение — говно:

1. **Perplexity ищет в интернете** → может найти старые версии законов, неофициальные источники, комментарии
2. **AI интерпретирует результаты поиска** → может неправильно понять или перепутать статьи
3. **Справочная база в промпте** — это костыль, который не решает проблему поиска
4. **Всегда будут новые кейсы** → невозможно предугадать все ошибки

### Что происходит сейчас:

```
Документ → Perplexity → Интернет → ???(говно) → AI → Анализ с ошибками
```

---

## ✅ РЕШЕНИЕ НА КОРНЮ: RAG СИСТЕМА

### Концепция:

**НЕ давать AI искать в интернете. Дать ему ПРОВЕРЕННУЮ базу законов.**

```
Документ → Анализ → RAG поиск → БАЗА ЗАКОНОВ РК → AI → Точный анализ
                                  (официальные тексты)
```

## 📦 ВАРИАНТ 1: ЛУЧШЕЕ РЕШЕНИЕ (RAG + Векторная БД)

### Что делать:

1. **Скачать все нужные законы РК** с adilet.zan.kz
2. **Загрузить в векторную БД** (Pinecone, Weaviate, или Supabase с pgvector)
3. **RAG поиск:** Для каждого запроса ищем релевантные статьи в БД
4. **AI анализ:** Claude/GPT генерирует анализ ТОЛЬКО на основе найденных статей
5. **Проверка:** Валидируем каждую упомянутую статью

    # Находим все упоминания статей
    mentioned = re.findall(r'статья (\d+)', analysis_text, re.IGNORECASE)

## 📦 ВАРИАНТ 2: СРЕДНИЙ (Claude + Function Calling)

### Концепция:

Использовать **Claude с function calling** для ПРОВЕРКИ каждой статьи перед упоминанием.

### Как работает:

```
AI хочет упомянуть статью
    ↓
Вызывает функцию verify_law(article_number)
    ↓
Функция проверяет в официальном API adilet.zan.kz
    ↓
Если статья существует и правильная → AI использует
    ↓
Если нет → AI ищет другую статью
```

### Код:

```python
# Отдельный микросервис для проверки статей

from flask import Flask, request, jsonify
import requests
from bs4 import BeautifulSoup

app = Flask(__name__)

@app.route('/verify_law', methods=['POST'])
def verify_law():
    code = request.json['code']
    article = request.json['article_number']
    
    # Запрос к adilet.zan.kz
    url = f"https://adilet.zan.kz/rus/docs/{code}#z{article}"
    response = requests.get(url)
    
    if response.status_code != 200:
        return jsonify({"exists": False})
    
    soup = BeautifulSoup(response.content, 'html.parser')
    article_div = soup.find('div', {'id': f'z{article}'})
    
    if not article_div:
        return jsonify({"exists": False})
    
    return jsonify({
        "exists": True,
        "text": article_div.get_text(),
        "url": url
    })
```

### Преимущества:

✅ Не нужна векторная БД  
✅ Проверка в реальном времени  
✅ Всегда актуальные данные  

### Недостатки:

❌ Медленнее (каждая статья = HTTP запрос)  
❌ Зависимость от доступности adilet.zan.kz  
❌ AI может всё равно ошибиться ПЕРЕД вызовом функции

## 📦 ВАРИАНТ 3: МИНИМАЛЬНЫЙ (GPT-4 + Пост-валидация)

### Концепция:

**Не мешать AI анализировать, но ПРОВЕРИТЬ результат перед отправкой.**

### Workflow:

```
AI делает анализ (как сейчас)
    ↓
Извлекаем все упомянутые статьи (regex)
    ↓
Проверяем каждую через API adilet.zan.kz
    ↓
Если ошибка → ОСТАНАВЛИВАЕМ и просим AI переделать
    ↓
Если всё ок → отправляем пользователю
```

### Код:

```python
# n8n: Post-Validation Node (Python)

import re
import requests

def validate_and_fix_analysis(analysis_text):
    """Проверяет все упомянутые статьи и исправляет ошибки"""
    
    # Находим все упоминания статей
    pattern = r'статья (\d+).*?(?:ГК РК|Гражданского кодекса)'
    mentions = re.findall(pattern, analysis_text, re.IGNORECASE)
    
    errors = []
    
    for article_num in mentions:
        # Проверяем статью 556 для аренды нежилых
        if article_num == "575":
            if "нежил" in analysis_text.lower():
                errors.append({
                    "wrong": "575",
                    "correct": "556",
                    "reason": "Статья 575 для ЖИЛЫХ, а не нежилых помещений"
                })
        
        # Проверяем статьи 406-410 для расторжения
        if article_num in ["406", "407", "408", "409", "410"]:
            if "расторжени" in analysis_text.lower():
                errors.append({
                    "wrong": article_num,
                    "correct": "401-405",
                    "reason": "Для расторжения статьи 401-405, не 406-410"
                })
    
    if errors:
        # Формируем запрос на исправление
        fix_prompt = f"""
        В твоём анализе обнаружены ошибки:
        
        {errors}
        
        ИСПРАВЬ анализ, заменив неправильные статьи на правильные.
        
        Исходный анализ:
        {analysis_text}
        """
        
        # Отправляем обратно в AI
        return {"status": "needs_fix", "prompt": fix_prompt}
    
    return {"status": "ok", "analysis": analysis_text}
```

### В n8n workflow:

```
┌──────────────┐
│ AI Analysis  │
└──────┬───────┘
       │
       ▼
┌──────────────────┐
│ Post-Validation  │
└──────┬───────────┘
       │
       ├─[OK]─────────→ Отправка пользователю
       │
       └─[ERROR]──────→ Fix Analysis → AI Analysis (retry)
```

### Преимущества:

✅ Минимальные изменения в текущем workflow  
✅ Работает с любой AI моделью  
✅ Быстро внедрить (1-2 часа)  

### Недостатки:

❌ Не на 100% защищает от новых типов ошибок  
❌ Нужно вручную добавлять правила валидации
